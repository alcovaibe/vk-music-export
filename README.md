# VK Music Export

Android-утилита для сохранения названий треков, исполнителей и структуры музыкальной коллекции ВК.

**Версия 0.3.0 — постоянная подпись, обновления поверх установленного приложения и GitHub Releases.** Код сбора написан, но вход и полнота получения музыки на реальном аккаунте ещё не проверены. Изменения сайта ВК могут потребовать адаптации парсера.

## Для личного использования

Приоритет — телефоны владельца на Android 16 и Android 17. Минимальная версия — Android 16 (API 36); более старые версии не поддерживаются. Compile/target SDK — 36. Автоматические проверки интерфейса выполняются на Android 16; Android 17 и реальный вход в ВК проверяются на устройстве владельца. Требования к возможному публичному выпуску рассматриваются отдельно.

## Возможности

- Вход на странице ВК внутри WebView; пароль и коды вводит владелец.
- Сбор «Моей музыки» или открытого плейлиста, автоматический поиск плейлистов в распознанном контейнере пользователя.
- Автопрокрутка и сохранение полученных порций на устройстве.
- Сохранение порядка и повторов внутри плейлистов; общий список объединяется только по известным идентификаторам ВК.
- Экспорт TXT, CSV, JSON и ZIP с отдельными плейлистами и отчётом.
- Поиск в сохранённой коллекции, системная светлая/тёмная тема, очистка коллекции и выход из ВК.

Приложение экспортирует метаданные. Аудиофайлы не скачиваются.

## Проверка на телефоне

1. Скачать подписанный APK из [последнего GitHub Release](../../releases/latest) и установить его. При следующем обновлении открывать новый APK поверх старого, без удаления приложения.
2. Нажать «Подключить ВКонтакте», войти на сайте ВК и нажать «Открыть мою музыку». Окна входа отображаются внутри приложения с адресом сайта.
3. Сначала нажать «Этот список». Используется мобильная версия ВК.
4. Проверить названия, исполнителей и количество в «Коллекции».
5. Открыть один плейлист вручную и повторить «Этот список».
6. Проверить «Собрать всё». Если список плейлистов не распознан, приложение сообщит об этом; ручной сбор остаётся доступен.
7. Сохранить ZIP и сверить плейлисты и report.txt.

Если вход или сбор не работают, откройте меню ⋮ → «Скопировать диагностику». Отчёт содержит версию Android/WebView, коды состояния и счётчики; пароль, cookies и названия треков в него не входят.

Полнота обнаружения плейлистов пока всегда обозначается как неподтверждённая. Совпадение счётчика треков не является гарантией полного и неизменного содержимого. Строки неизвестной разметки не выдумываются.

Браузерная сессия сохраняется при переходах между коллекцией, экспортом и экраном ВК. Сбор выполняется на открытом экране ВК. Возврат к коллекции, уход в фон или кнопка остановки прерывают сбор и сохраняют полученный результат. Повторный запуск перечитывает выбранный источник с начала; полноценное возобновление с последней позиции пока не реализовано. Новый сбор всей коллекции заменяет предыдущий после проверки доступа к «Моей музыке».

## Вход в ВК

Используется веб-сессия сайта ВК в Android WebView. Всплывающие окна получают JavaScript, DOM storage и одинаковые настройки cookies; смена экрана не уничтожает браузер. Доступность музыкальной страницы проверяется отдельно: сохранённая cookie сама по себе не считается успешным подключением. Пароли, коды подтверждения, cookies и токены не читаются скриптом сбора и не экспортируются.

Это не интеграция нативного VK ID SDK: для неё нужны зарегистрированное приложение VK ID, client_id и его настройки. Вход во внешнем браузере не переносит автоматически его cookies во встроенный WebView. Переходы в другие приложения пока не поддерживаются — выбирайте способ входа на сайте ВК.

- Android SDK Platform 36 и Build Tools 36.0.0.

## Обновления и GitHub Releases

После каждого успешного `push` в `main` (или ручного запуска workflow на `main`) CI автоматически создаёт отдельный GitHub Release с APK, `SHA256SUMS.txt`, сведениями о сборке, публичным сертификатом и результатом проверки обновления. Сначала должны пройти unit-тесты, парсер, lint, интерфейс и проверка установки поверх предыдущего APK. На pull request секреты подписи и публикация недоступны. Ссылка на последнюю сборку доступна в приложении: ⋮ → «Обновления на GitHub». Для приватного репозитория браузер должен быть авторизован в GitHub.

Пакет `app.alcovaibe.vkmusicexport` и release-подпись постоянны. `versionName` берётся из `version.properties`, CI `versionCode` = `1000 + GITHUB_RUN_NUMBER` этого workflow. Каждый новый запуск получает больший код, повтор того же запуска не заменяет уже опубликованные файлы. Не переименовывайте/не пересоздавайте workflow со сбросом счётчика без переноса нижней границы номера версии.

Обновление — обычная установка подписанного APK поверх установленного приложения: Android сохраняет коллекцию, настройки и хранилище WebView. Подтверждение установки в Android остаётся; скрытой установки, загрузки исполняемых патчей и собственной системы обновления кода нет. Это не дифференциальная загрузка: скачивается целый APK. Сервер ВК может независимо завершить сессию.

**Однократный переход с debug 0.1/0.2:** ранее CI создавал временные ключи; их закрытая часть не сохранялась. Для перехода нужно сохранить ZIP, удалить старый debug APK и установить release APK. ZIP служит внешней копией: импорта обратно пока нет. Дальнейшие release-сборки обновляются без удаления приложения.

Постоянный ключ хранится в секрете репозитория `ANDROID_SIGNING` (JSON: `keystoreBase64`, `password`, `alias`). В git хранится только публичный `config/release-certificate.pem`; CI сверяет его отпечаток с APK и прекращает выпуск при несовпадении. Отсутствие секрета — ошибка, временный ключ автоматически не генерируется. Не удаляйте и не меняйте этот секрет без сохранения исходного ключа: потеря подписи нарушит последующие обновления.

Для локальной release-сборки задайте `RELEASE_KEYSTORE_PATH`, `RELEASE_STORE_PASSWORD`, `RELEASE_KEY_ALIAS`, `APP_VERSION_CODE` и выполните `./gradlew assembleRelease`. Без ключа локальная release-сборка остаётся неподписанной и не предназначена для установки.

`tools/upgrade-check.sh` работает только в одноразовом rooted AVD: устанавливает две обычные R8 release-сборки с одной подписью и возрастающим `versionCode`, проверяет SHA-256 сохранённой коллекции до/после `adb install -r` и её отображение в новом APK. Это синтетическая коллекция, без аккаунта и данных ВК.

## Основа и разработка

Проект полностью импортирован из приватного PulseAI отдельным коммитом, затем его функционал заменён: [происхождение](docs/IMPORT.md). Исходный PulseAI не изменён.

[План реализации](PLAN.md) • [Известные ограничения](docs/LIMITATIONS.md)

Сессии, выгрузки и ключи не добавляются в git. Собственного сервера и аналитических SDK нет; WebView связывается непосредственно с ВК.


Если только тестовая инфраструктура помешала публикации уже собранных APK, workflow `Verify and publish existing signed APKs` принимает номера исходных Android workflow runs. Он проверяет успешные исходные build/interface jobs, коммиты, SHA-256, пакет, версии и постоянную подпись двух APK, повторяет установку поверх и публикует **те же бинарные файлы**. Исходный коммит APK сохраняется в метаданных; тег указывает на коммит проверки только после сверки идентичности дерева `app`, Gradle, wrapper, конфигурации и версии с исходной сборкой. Ключ подписи этому workflow не нужен. Старое восстановление не переводит ссылку Latest на меньший versionCode. Это ручной путь восстановления CI; обычные новые сборки публикуются автоматически основным workflow.

### Мобильный браузер

Встроенное окно ВК и окно авторизации используют Chrome-совместимый User-Agent без маркеров `wv` и `Version/4.0`. Версия Chromium берётся с устройства; Client Hints согласуются через AndroidX WebKit при поддержке движком. Реализация остаётся WebView, не получает сеанс внешнего Chrome и не гарантирует, что ВК перестанет различать браузеры. Парсер читает метаданные музыкальных страниц после входа в этом же окне.

# 0.7.0 — проверка прямого музыкального доступа и одного аудиофайла

Настройки → «Прямой доступ ВК · эксперимент». Нативный read-only API-адаптер получает первые 10 треков и первые 10 подборок с уже выданным владельцу токеном ВК. Автоматическое получение музыкального токена пока не реализовано: одного входа в Chrome для этой проверки недостаточно. Токен вводится только на устройстве, хранится отдельным AES-GCM конвертом AndroidKeyStore и не попадает в журнал.

Выборка сохраняется в основную коллекцию после явного подтверждения, всегда как частичная; длительность и album metadata доступны в JSON/CSV. Одна композиция скачивается из доступной прямой ссылки или ограниченного HLS VOD. Media3 определяет фактический поток: MP3 сохраняется как MP3, AAC — как M4A без перекодирования. Ошибка сегмента, неизвестный кодек и несоответствие длительности не создают готовый файл. Есть отмена, проверка SHA-256 и экспорт через системный выбор документа. При уходе из приложения операция останавливается; массовой фоновой очереди пока нет.

Это проверяемый первый прототип. Успешная работа API и скачивания на аккаунте владельца ещё не подтверждена. [Устройство и ограничения](docs/NATIVE-MUSIC.md) · [Исследование источников](docs/RESEARCH-2026-10-20.md).

# 0.5.3 — диагностика E6 внутри плейлиста

На телефоне владельца панель 0.5.2 появилась, но «Сбор» вернул E6 и внутри отдельного плейлиста. Подтверждён запуск кода и отсутствие известных контейнеров при проверке. Это не доказательство блокировки ВК; успешный сбор ещё не подтверждён. Селекторы не расширены вслепую.

Добавлена отдельная кнопка «Копировать диагностику разметки» в «Сбор из Chrome». Создать отдельную закладку **VKM Layout**, заменить весь адрес, открыть проблемный плейлист и запустить её через подсказки адресной строки. После «VKM layout 1» нажать «Скачать диагностику» и передать **vk-layout.json** разработчику. Не импортировать файл как музыку. Прежний сборщик/маркер 0.5.2 сохранён; этот выпуск сам E6 не исправляет.

Диагностический URL — 4137 ASCII-символов, жёсткий предел 4950. Программа выводит только фиксированный словарь признаков и тегов, их счётчики и до 12 цепочек по 8 предков. Нет произвольных значений атрибутов, текста, HTML, DOM-сериализации, идентификаторов пользователя/плейлиста, URL, data-audio, cookies, полей или хранилищ. Нет запросов и стороннего кода. Вывод — JSON schema 1, kind vkm-layout; фиксированные перечисления host_kind/route_kind/ready_state. Максимум 100 КБ; значения счётчиков ограничены 10000. limited отмечает ограничение счётчиков признаков. Цепочки всегда ограничены; отсечённая структура не гарантирует правильную область списка. Только Light DOM: iframe/shadow DOM не просматриваются. Признаки считаются по всей странице, включая невидимые элементы, это не выгрузка музыки и не доказательство полноты.

Проверки: фактический URL и скачивание в Chromium на синтетическом мобильном плейлисте, запрет чтения текста/HTML/полей, отсутствие подставленных секретов в JSON; реальная нативная кнопка, clipboard и однострочное URI-поле Android; обычные проверки сборщика/импорта. Проверка обновления — поверх подписанной 0.5.2 (1046). Реальная диагностика страницы будет доступна только после получения файла с телефона.

Следующий шаг: сопоставить счётчики/вложенность с исходным E6, проверить гипотезу мобильного контейнера (например au_search_items) и исключение рекомендаций. Если фиксированный словарь не узнаёт страницу, ограниченный отчёт так и остаётся недостаточным доказательством; успешный сбор не объявлять.

# VK Music Export

Android-приложение для хранения и экспорта названий треков, исполнителей и структуры музыкальной коллекции ВК.

**0.5.2 — исправление обрезания закладки на Android и адаптация новой разметки VK Music.** В сохранённом владельцем адресе 0.5.1 обнаружен точный префикс первых 5000 символов исходной закладки после учёта URL-кодирования. Android по умолчанию ограничивает однострочное поле этим размером. Новый адрес — 4857 ASCII-символов, сборка и приложение запрещают адрес длиннее 4950. Код самодостаточен: без сервера, динамической подгрузки JavaScript и eval. Успешный реальный сбор ВК ещё нужно подтвердить на телефоне.

Обновление APK не меняет закладку Chrome. Заново скопируйте код и замените адрес прежней закладки. В конце — `/*VKM_END_052*/`. Сообщение запуска — `VKM 0.5.2`, ошибка создания панели — фиксированное `INIT`.

Короткая панель показывает число треков / плейлистов и номер прохода. «Стоп» останавливает сбор; после остановки та же кнопка становится X для закрытия панели. E0 означает остановку прокрутки и не гарантирует полноту. E6 — неизвестная разметка; E10 — виртуализированные порции без позиций не удалось объединить. Полная причина отображается при импорте.

## Сбор из Chrome

1. В приложении → «Сбор из Chrome» → «Скопировать закладку».
2. В Chrome сохранить любую страницу в закладки через ⋮ → ★. Изменить закладку: имя `VKM Export`, адрес — скопированный код целиком, начиная с `javascript:`.
3. Открыть «Мою музыку» или отдельный плейлист ВК. В адресной строке набрать `VKM Export`, выбрать закладку из подсказок. Нажатие обычного поиска не запускает код.
4. Появится «VKM 0.5.2». Нажать ОК. Затем в панели сборщика нажать «Сбор». Дождаться остановки или остановить вручную, затем «JSON».
5. Вернуться в приложение → «Импорт JSON», выбрать файл из загрузок. Проверить числа и подтвердить импорт. При совпадении источника заменяется только этот список; предупреждение показывает старое и новое количество.
6. Повторить для каждого нужного плейлиста. Каталог обнаруженных плейлистов содержит названия и идентификаторы; их треки нужно собирать отдельно.

Окно Chrome не является WebView. Приложение не получает его сессию и не запускает код автоматически. Установка и выполнение закладки требуют действий пользователя; ограничения Chrome/сайта и новая разметка ВК могут помешать сбору. Собственного сервера нет.

Сборщик читает только метаданные музыкальной страницы и прокручивает открытый список. Не читает пароли, значения полей, cookies, токены, HTML, хранилища или audio URL; не делает fetch/XHR. Параметры URL и приватные ключи плейлистов в файл не попадают. Непонятная разметка не подменяется выдуманными треками.

Порядок и повторы сохраняются в доступных данных. При известных позициях порции объединяются по ним; неоднозначная виртуализация без позиций останавливает сбор с частичным результатом. Конец прокрутки/совпадение счётчика не являются гарантией полноты. Лимиты: 600 проходов по ~800 мс, 10 000 треков на список, 1000 плейлистов в каталоге, 500 символов в имени, 10 МБ на JSON. Достижение лимита отражается в причине остановки.

Импорт строго проверяет протокол, размеры, типы, позиции и идентификаторы. Предпросмотр, отмена, подтверждение и атомарное сохранение защищают существующую коллекцию. Каталог не очищает ранее собранные треки. Импортируемые строки и URI в логи не пишутся. Ранее сохранённые коллекции, поиск и экспорт TXT/CSV/JSON/ZIP работают как раньше.

## Проверка на телефоне

Подписанный APK из [последнего GitHub Release](../../releases/latest) устанавливается поверх существующей release-версии без удаления. Для первого теста соберите небольшой плейлист и проверьте число, названия, повторы и порядок после импорта. Затем проверьте «Мою музыку» и каталог плейлистов. Нераспознанная разметка или отсутствие панели — результат для дальнейшей адаптации, а не успешный сбор.

Нативная диагностика: настройки → «Копировать лог» / «Другие логи → Поделиться JSON-файлом». Приложение видит установленную версию Chrome, запуск браузера и этапы импорта; страницы, сеть, DOM и консоль внешнего Chrome ему недоступны.

Минимум Android 16/API 36; compile/target SDK 36. Аудиофайлы не скачиваются. Пользовательские выгрузки, сессии и ключи в git не добавляются.

## Обновления и GitHub Releases

После каждого успешного `push` в `main` (или ручного запуска workflow на `main`) CI автоматически создаёт отдельный GitHub Release с APK, `SHA256SUMS.txt`, сведениями о сборке, публичным сертификатом и результатом проверки обновления. Сначала должны пройти unit-тесты, парсер, lint, интерфейс и проверка установки поверх предыдущего APK. На pull request секреты подписи и публикация недоступны. Ссылка на последнюю сборку доступна в приложении: ⋮ → «Обновления на GitHub». Для приватного репозитория браузер должен быть авторизован в GitHub.

Пакет `app.alcovaibe.vkmusicexport` и release-подпись постоянны. `versionName` берётся из `version.properties`, CI `versionCode` = `1000 + GITHUB_RUN_NUMBER` этого workflow. Каждый новый запуск получает больший код, повтор того же запуска не заменяет уже опубликованные файлы. Не переименовывайте/не пересоздавайте workflow со сбросом счётчика без переноса нижней границы номера версии.

Обновление — обычная установка подписанного APK поверх установленного приложения: Android сохраняет коллекцию, настройки и прежние данные приложения. Новый код не обращается к прежнему хранилищу WebView. Подтверждение установки в Android остаётся; скрытой установки, загрузки исполняемых патчей и собственной системы обновления кода нет. Это не дифференциальная загрузка: скачивается целый APK. Сервер ВК может независимо завершить сессию.

**Однократный переход с debug 0.1/0.2:** ранее CI создавал временные ключи; их закрытая часть не сохранялась. Для перехода нужно сохранить ZIP, удалить старый debug APK и установить release APK. ZIP служит внешней копией: импорта обратно пока нет. Дальнейшие release-сборки обновляются без удаления приложения.

Постоянный ключ хранится в секрете репозитория `ANDROID_SIGNING` (JSON: `keystoreBase64`, `password`, `alias`). В git хранится только публичный `config/release-certificate.pem`; CI сверяет его отпечаток с APK и прекращает выпуск при несовпадении. Отсутствие секрета — ошибка, временный ключ автоматически не генерируется. Не удаляйте и не меняйте этот секрет без сохранения исходного ключа: потеря подписи нарушит последующие обновления.

Для локальной release-сборки задайте `RELEASE_KEYSTORE_PATH`, `RELEASE_STORE_PASSWORD`, `RELEASE_KEY_ALIAS`, `APP_VERSION_CODE` и выполните `./gradlew assembleRelease`. Без ключа локальная release-сборка остаётся неподписанной и не предназначена для установки.

`tools/upgrade-check.sh` работает только в одноразовом rooted AVD: устанавливает две обычные R8 release-сборки с одной подписью и возрастающим `versionCode`, проверяет SHA-256 сохранённой коллекции до/после `adb install -r` и её отображение в новом APK. Это синтетическая коллекция, без аккаунта и данных ВК.

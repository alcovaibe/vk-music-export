# VK Music Export

Android-приложение для хранения и экспорта названий треков, исполнителей и структуры музыкальной коллекции ВК.

**0.4.0 — промежуточный этап: настоящий Google Chrome для входа. Сбор музыки из Chrome пока недоступен.** Этот объём выбран владельцем после воспроизведения белой страницы VK ID в WebView. Причина белой страницы не доказана; переход не объявляется её исправлением внутри WebView.

## Что работает

- «Открыть ВК в Chrome» запускает обычное приложение Google Chrome (`com.android.chrome`) на `https://vk.ru/`.
- Вход, подтверждения, выход из ВК и браузерная сессия принадлежат Chrome. Приложение не получает cookies, пароли или токены Chrome и не объявляет пользователя авторизованным по факту открытия браузера.
- Ранее сохранённая коллекция, поиск, порядок и повторы треков сохраняются. Данные не мигрируют и не переписываются при запуске Chrome.
- Экспорт имеющейся коллекции в TXT, CSV, JSON и ZIP с отдельными плейлистами и отчётом.
- Системная светлая/тёмная тема, очистка коллекции и нативная диагностика текущего/предыдущего запуска.

Встроенный WebView, дополнительные окна, выбор профиля и подмена UA/Client Hints удалены, зависимость AndroidX WebKit исключена. Кнопок сбора в этой версии нет. Исходник прежнего DOM-парсера оставлен как заготовка для дальнейшей разработки; приложение его не запускает.

## Проверка на телефоне

1. Установить подписанный APK из [последнего GitHub Release](../../releases/latest) поверх существующей release-версии, без удаления приложения.
2. Нажать «Открыть ВК в Chrome». Должно открыться настоящее приложение Chrome, а не окно VK Music Export.
3. Завершить вход на сайте ВК. Если сессия Chrome уже существует, повторный ввод может не понадобиться. Приложение не заставляет выходить из действующей сессии.
4. Вернуться кнопкой «Назад» или через список последних приложений. Проверить сохранённую коллекцию и экспорт.
5. Если браузер не открылся, проверить, что Google Chrome установлен и включён. Автоматической замены другим браузером нет.

Настройки → «Копировать лог» / «Другие логи → Поделиться JSON-файлом». Диагностика содержит версии приложения, Android и установленного Chrome, отправку Intent и нативный жизненный цикл. Страницы, сеть, DOM, UA/Client Hints и успешность входа внешнего Chrome приложению не видны. Факт отправки Intent не доказывает загрузку ВК или авторизацию.

Минимальная версия — Android 16 (API 36); compile/target SDK 36. Проверки Android 17 и реального входа выполняются владельцем на телефоне. Собственного сервера и аналитических SDK нет. Аудиофайлы не скачиваются.

## Сборка

- Android Studio с поддержкой AGP 9.2.1; JDK 21 из конфигурации импортированного проекта.
- Android SDK Platform 36 и Build Tools 36.0.0.
- Android 16+ (API 36); namespace/applicationId: `app.alcovaibe.vkmusicexport`.

```sh
./gradlew testDebugUnitTest lintDebug assembleDebug
node --test tools/extractor.test.cjs
# С подключённым эмулятором или телефоном:
./gradlew connectedDebugAndroidTest
```

Debug APK: `app/build/outputs/apk/debug/app-debug.apk` — только для разработки и CI. Для телефона владельца используйте **release APK из Releases**.

## Обновления и GitHub Releases

После каждого успешного `push` в `main` (или ручного запуска workflow на `main`) CI автоматически создаёт отдельный GitHub Release с APK, `SHA256SUMS.txt`, сведениями о сборке, публичным сертификатом и результатом проверки обновления. Сначала должны пройти unit-тесты, парсер, lint, интерфейс и проверка установки поверх предыдущего APK. На pull request секреты подписи и публикация недоступны. Ссылка на последнюю сборку доступна в приложении: ⋮ → «Обновления на GitHub». Для приватного репозитория браузер должен быть авторизован в GitHub.

Пакет `app.alcovaibe.vkmusicexport` и release-подпись постоянны. `versionName` берётся из `version.properties`, CI `versionCode` = `1000 + GITHUB_RUN_NUMBER` этого workflow. Каждый новый запуск получает больший код, повтор того же запуска не заменяет уже опубликованные файлы. Не переименовывайте/не пересоздавайте workflow со сбросом счётчика без переноса нижней границы номера версии.

Обновление — обычная установка подписанного APK поверх установленного приложения: Android сохраняет коллекцию, настройки и прежние данные приложения. Новый код не обращается к прежнему хранилищу WebView. Подтверждение установки в Android остаётся; скрытой установки, загрузки исполняемых патчей и собственной системы обновления кода нет. Это не дифференциальная загрузка: скачивается целый APK. Сервер ВК может независимо завершить сессию.

**Однократный переход с debug 0.1/0.2:** ранее CI создавал временные ключи; их закрытая часть не сохранялась. Для перехода нужно сохранить ZIP, удалить старый debug APK и установить release APK. ZIP служит внешней копией: импорта обратно пока нет. Дальнейшие release-сборки обновляются без удаления приложения.

Постоянный ключ хранится в секрете репозитория `ANDROID_SIGNING` (JSON: `keystoreBase64`, `password`, `alias`). В git хранится только публичный `config/release-certificate.pem`; CI сверяет его отпечаток с APK и прекращает выпуск при несовпадении. Отсутствие секрета — ошибка, временный ключ автоматически не генерируется. Не удаляйте и не меняйте этот секрет без сохранения исходного ключа: потеря подписи нарушит последующие обновления.

Для локальной release-сборки задайте `RELEASE_KEYSTORE_PATH`, `RELEASE_STORE_PASSWORD`, `RELEASE_KEY_ALIAS`, `APP_VERSION_CODE` и выполните `./gradlew assembleRelease`. Без ключа локальная release-сборка остаётся неподписанной и не предназначена для установки.

`tools/upgrade-check.sh` работает только в одноразовом rooted AVD: устанавливает две обычные R8 release-сборки с одной подписью и возрастающим `versionCode`, проверяет SHA-256 сохранённой коллекции до/после `adb install -r` и её отображение в новом APK. Это синтетическая коллекция, без аккаунта и данных ВК.

# План реализации VK Music Export

Дата: 18 октября 2026 года.
Репозиторий: alcovaibe/vk-music-export (private).
Статус: начата реализация 0.1.0 на основе полного импорта PulseAI. Написаны WebView-вход, DOM-сбор, обход плейлистов, локальное сохранение, интерфейс и экспорт. Сборка проверяется в CI. Вход и полнота на реальном аккаунте ещё не проверены. Room и продолжение с точной последней позиции остаются в плане.

## 1. Цель и согласованный объём

Android-утилита получает доступную владельцу коллекцию музыки ВК и сохраняет:
- полный доступный список раздела «Моя музыка»;
- все обнаруженные созданные и сохранённые плейлисты и их названия;
- треки каждого плейлиста в исходном порядке;
- объединённый список уникальных аудиозаписей из всех источников.

Основные поля: название и исполнитель. Дополнительно сохраняем идентификаторы ВК, номер позиции, источник и длительность, когда они доступны.
Повторы внутри плейлистов сохраняются. Удаление повторов применяется только к объединённому списку.
Скачивание аудиофайлов и перенос в другие музыкальные сервисы в первую версию не входят.

## 2. Предварительные технические решения

- Kotlin, Jetpack Compose, coroutines, Android WebView.
- Рабочий минимум: Android 8.0 (API 26); конкретные compile/target SDK и версии зависимостей фиксируем при создании проекта после проверки официальных релизов.
- Обработка и промежуточное хранение на телефоне; собственный сервер не требуется.
- Room для результатов сканирования и контрольных точек; DataStore для несекретных настроек.
- Системный выбор файла/папки для сохранения; общий доступ ко всему хранилищу не требуется.
- Обычная авторизация VK ID не считается подтверждённым доступом к музыкальной коллекции.
- Предпочтительный исследуемый путь — чтение музыкальных страниц в авторизованной WebView. Адаптер запросов веб-интерфейса допускается как отдельный вариант только после проверки реального поведения и доступных владельцу данных.
- WebView пока является гипотезой реализации: вход и доступ к музыке в ней необходимо подтвердить на устройстве.
- Структура данных и экспорт не должны зависеть от конкретной разметки ВК.

## 3. Этапы и критерии завершения

### Этап 0. Репозиторий и основа проекта

Результат:
- README, этот план, правила исключения локальных настроек, cookies, ключей, выгрузок и личных данных из git.
- Минимальный Android-проект с закреплёнными зависимостями и Gradle Wrapper.
- GitHub Actions: сборка debug APK, unit-тесты ядра, Android Lint.
- Минимальные разрешения GitHub Actions; пользовательские данные не участвуют в CI.
- Пакет и название приложения фиксируются в проекте; рабочее название VK Music Export.

Готово, когда чистая сборка проходит в CI, а debug APK доступен как артефакт успешного запуска.
Сейчас созданы репозиторий, README и план реализации; Android-проект и CI пока запланированы.

### Этап 1. Диагностический APK — проверка реализуемости

Результат:
- Экран открытия ВК, ручного входа владельцем и диагностики доступа.
- Проверка переходов авторизации, SMS/2FA и капчи, если они появляются: ввод выполняет пользователь.
- Проверка мобильной/полной музыкальной страницы по фактическому поведению сайта.
- Чтение названия и исполнителя нескольких треков, определение идентификаторов, если страница их предоставляет.
- Обнаружение хотя бы одного плейлиста и чтение его содержимого.
- Обезличенный отчёт: версия Android/WebView, этап, код ошибки, количества; без HTML страниц, cookies, токенов, URL с секретами и содержимого форм входа.

Готово, когда APK установлен на телефоне владельца, вход проходит, читаются треки «Моей музыки» и одного плейлиста.
Если вход или чтение не работают, сохраняем конкретный результат и корректируем способ доступа. До решения этой проблемы полнота экспорта не заявляется.
Это первый контрольный рубеж; полноценный UI не блокирует исследование.

### Этап 2. Полная загрузка «Моей музыки»

Результат:
- Последовательная подгрузка страниц/участков списка.
- Сбор каждой порции до возможного удаления строк из DOM при виртуализации.
- Различение повторного наблюдения той же строки и повторного вхождения трека в список.
- Тайм-ауты, ограниченные повторы, пауза при ограничении запросов, распознавание истёкшей сессии.
- Проверка числа полученных позиций против счётчика ВК, когда он доступен.
- Обнаружение зацикленной пагинации и повторяющихся страниц.

Готово, когда короткая и длинная коллекции обрабатываются до подтверждённого конца либо получают явный статус неполноты.
Несколько прокруток без новых строк сами по себе не доказывают, что коллекция собрана полностью.

### Этап 3. Все плейлисты

Результат:
- Постраничное обнаружение созданных и сохранённых плейлистов.
- Идентификация плейлиста по owner/id и другим предоставленным сайтом признакам; технические ключи доступа не включаются в обычный экспорт.
- Отдельная обработка каждого плейлиста, включая сохранённые плейлисты другого владельца, доступные текущему пользователю.
- Сохранение названия, порядка и повторных вхождений треков.
- Пустые, удалённые и недоступные плейлисты отражаются в результате.
- Коллекция ограничена разделами пользователя; рекомендации и чужие несохранённые подборки автоматически в неё не включаются.

Готово, когда проверены созданный, сохранённый, пустой и длинный плейлисты; обнаруженные ограничения явно показаны.
Недоступные странице данные не восстанавливаются и не выдаются за успешно полученные.

### Этап 4. Модель данных, прогресс и продолжение

Сущности:
- Track: локальный ключ, ownerId/audioId при наличии, название, исполнитель, доступная длительность.
- Playlist: локальный ключ, удалённый идентификатор при наличии, название, источник, ожидаемое число позиций.
- PlaylistEntry: плейлист, номер позиции, ссылка на трек. Одинаковая песня может иметь несколько записей.
- ScanRun / ScanSource: время начала и окончания, контрольные точки, счётчики, ошибки и статус полноты.

Результат:
- Сохранение каждой успешно обработанной порции.
- Продолжение после остановки с повторной проверкой сессии и границы последней порции.
- Проверка изменений коллекции между запусками: при сдвиге списка повторное сканирование затронутого источника.
- Объединение аудиозаписей по ownerId/audioId, когда они доступны.
- Совпадение названия и исполнителя без идентификатора помечается как возможный дубль; разные записи автоматически не склеиваются.

Готово, когда остановка и повторный запуск не теряют уже собранные данные и не создают дубли из-за повторной загрузки.
Состояния источника: полон по проверенным признакам / полнота не подтверждена / частично / недоступен / ошибка / остановлен пользователем.

### Этап 5. Экспорт

Результат:
- TXT: «Исполнитель — Название», общий список и отдельные плейлисты.
- CSV: структурированная таблица с источником/плейлистом, позицией и идентификаторами.
- JSON: версионированная структура коллекции с плейлистами, вхождениями и отчётом о полноте.
- ZIP: общий TXT, отдельные TXT плейлистов, CSV, JSON и отчёт.
- Имена файлов очищаются от недопустимых символов; одинаковые названия плейлистов получают устойчивый суффикс.
- UTF-8, корректное экранирование CSV и переносов строк.
- Выгрузка частичного результата разрешена с явной отметкой о неполноте.
- Прерывание сохранения не считается успешным экспортом.

Готово, когда файлы открываются на Android и компьютере, порядок и повторы сохранены, а отчёт соответствует состоянию сканирования.

### Этап 6. Интерфейс

Экраны:
1. Старт: описание, вход, состояние подключения.
2. Сбор: текущий источник, реальные счётчики, пауза/остановка, продолжение.
3. Коллекция: «Моя музыка», плейлисты, общий список; поиск по названию/исполнителю.
4. Экспорт: выбор состава и формата, системное сохранение.
5. Диагностика и управление локальными данными/сессией.

Результат:
- Русский интерфейс, светлая/тёмная тема, нормальная работа кнопки «Назад».
- Доступный размер элементов и поддержка увеличенного шрифта.
- Проценты показываются только при известном общем количестве; иначе показываются реальные счётчики.
- Сканирование первой версии работает при открытом приложении; при уходе в фон состояние сохраняется, непрерывная фоновая работа не обещается.

Готово, когда основные сценарии проходятся на телефоне без служебных действий разработчика.

### Этап 7. Проверка и первая пригодная для использования сборка

Результат:
- Тесты парсера на синтетических/обезличенных примерах разметки и ответов.
- Тесты пагинации: повтор порции, тайм-аут, пустой ответ, истёкшая сессия, ограничение запросов.
- Тесты сохранения позиций, повторов, идентификаторов и неполной выгрузки.
- Тесты экспортёров: кириллица, emoji, кавычки, разделители, переносы строк, одинаковые имена.
- Ручная проверка на телефоне владельца: вход, большая коллекция, плейлисты, прерывание/продолжение, экспорт.
- Инструкция сборки, установки и известных ограничений.
- Подписание пригодного для обновлений APK с ключом, контролируемым владельцем; ключ не коммитится.
- APK и заметки о версии только в этом приватном репозитории.

Готово, когда CI проходит, проверка на устройстве завершена, полнота каждого источника честно отражена и файлы экспорта сверены с доступной коллекцией.

## 4. Работа с сессией и пользовательскими данными

- Пользователь самостоятельно вводит пароль и коды на странице ВК; приложение не создаёт собственную форму сбора пароля.
- Скрипты извлечения выполняются только на проверенных музыкальных страницах, после входа; на страницах авторизации не запускаются.
- Для чтения данных предпочтителен evaluateJavascript с возвратом ограниченного JSON. Широкий addJavascriptInterface для стороннего контента не используется.
- Внешние переходы проверяются по схеме и точному домену; непроверенные intent/deep-link переходы не выполняются автоматически.
- HTTPS, стандартная проверка сертификатов; ошибки TLS не игнорируются.
- Cookies остаются в локальном хранилище WebView. Секреты и выгрузки исключаются из логов, отчётов, git и резервного копирования приложения.
- Выход очищает сессию; удаление собранной коллекции и экспортированных файлов — отдельные действия.
- Сессия в браузере телефона и сессия WebView не считаются общей: вход в Chrome не гарантирует вход в приложении.
- Точные домены входа/редиректов определяются проверкой реального входа; список не расширяется произвольно.
- Сторонний аналитический SDK и сервер для загрузки личной коллекции не нужны.

## 5. Риски и принятые способы обработки

| Риск | Поведение |
|---|---|
| ВК не допускает нужный вход в WebView | Останавливаем этап 1, фиксируем причину, исследуем другой способ доступа до развития UI |
| Разметка/веб-запросы ВК изменились | Отдельный адаптер, тестовые примеры, явная ошибка несовместимости |
| Часть коллекции скрыта/недоступна | Отчёт о неполноте, никакого утверждения «выгружено всё» |
| Недоступный трек без читаемого названия | Сохраняем доступные поля и статус, название не придумываем |
| Сайт возвращает рекомендации рядом с музыкой | Сбор только из определённого источника/контейнера |
| Список меняется во время сканирования | Проверка границ/счётчиков, повтор источника или отметка о неполноте |
| Истекла сессия, капча или 2FA | Пауза и ручное действие владельца в приложении |
| Нет достоверного счётчика или признака конца | Статус «полнота не подтверждена» |
| Неизвестные идентификаторы | Осторожное объединение; возможные дубли показываются отдельно |
| Процесс приложения завершён Android | Контрольные точки; продолжение после запуска, без обещания постоянной фоновой работы |

## 6. Порядок разработки в git

- Вся разработка, документация и сборки ведутся в alcovaibe/vk-music-export.
- main хранит согласованное состояние; рабочие изменения — в тематических ветках с небольшими коммитами и PR.
- Для начальной фиксации плана допустим коммит прямо в main.
- Реальные выгрузки, HTML личных страниц, cookies и логи входа в репозиторий не добавляются.
- Публикация репозитория или релиза вне приватного проекта не входит в текущую задачу.
- Код BitChord и других проектов не копируется без отдельной проверки применимых лицензий. Первая реализация пишется самостоятельно.

## 7. Следующая конкретная поставка

Диагностический debug APK и инструкция на русском:
1. открыть ВК и войти;
2. открыть «Мою музыку»;
3. выполнить диагностику;
4. открыть один плейлист и повторить;
5. сверить счётчики и сохранить обезличенный отчёт.

До прохождения этого рубежа подтверждены только найденные подходы и документация, а не работоспособность полного экспорта на конкретном аккаунте.

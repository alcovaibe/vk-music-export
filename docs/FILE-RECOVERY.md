# Восстановление связи с сохранёнными файлами — 0.9.13

Кнопка «Проверить сохранённые файлы» в музыкальном разделе открывает нижнюю панель. Проверка явная, локальная и не требует токена ВК. Список строится из всех записей files в noBackupFilesDir/audio-export.db, а не последних пяти файлов. Причины: запись MediaStore не найдена, Android отказал в чтении, изменился владелец, публикация не завершена, файл вне разрешённой папки, изменился размер или SHA-256, изменилось имя/местоположение, ошибка чтения. Неудачная проверка не доказывает повреждение аудио. Отключать сверку перед записью обложек нельзя.

## Автоматическое восстановление

«Найти автоматически» проверяет записи заново и ищет среди доступных приложению аудиофайлов, принадлежащих его пакету, в Music. Общие разрешения READ_MEDIA_AUDIO/управления всеми файлами не добавляются. Невидимые/чужие файлы требуют ручного выбора. Кандидаты сначала отбираются по размеру, затем полностью сверяются по SHA-256. Имя, исполнитель, название, длительность или предположение по папке не заменяют совпадение байтов.

Только единственное совпадение принимается после повторной проверки. Несколько одинаковых копий — неоднозначность; копия, связанная с другой записью, не присваивается. Если совпадения нет, исходная причина остаётся видна вместе с результатом поиска. Обновляются URI/имя/папка в учёте, контрольная точка и только существующая история. Состояния задач не меняются. Для явно восстановленных связей разрешено чтение/добавление обложек к собственным файлам вне папки экспорта, но только внутри Music; посторонние файлы по-прежнему не перезаписываются. Такое восстановление может снять право на удаление трека из ВК: оно по-прежнему требует проверенной копии именно в Music/VK Music Export/Моя музыка.

## Ручной выбор

«Выбрать файл» открывает ACTION_OPEN_DOCUMENT для аудио. Отмена не меняет учёт. Выбранный документ читается в отдельную приватную временную копию; размер ограничен пределом аудиозагрузки и свободным местом. Парсер проверяет реальный поддерживаемый аудиоформат и длительность с прежним допуском; содержимое копируется без перекодирования. Небезопасная/неподдерживаемая структура тегов отклоняется. Доступ к общей медиатеке не запрашивается, долговременное разрешение к внешнему документу не требуется.

Панель показывает выбранное имя и результат сверки. При отличии SHA-256 пользователь явно предупреждён: совпадение формата/длительности не доказывает, что это та же песня. Только кнопка «Восстановить копию» публикует отдельный файл в Music/VK Music Export/Восстановленные и заменяет связь в учёте. Это осознанный импорт выбранного пользователем файла, а не автоматическое признание изменённого файла прежним. Выбранный исходник и старая копия не изменяются/не удаляются. Имя новой копии строится по прежним правилам, совпадения получают суффикс.

Перед публикацией сохраняется AtomicFile-журнал saved-file-recovery/transaction.json с прежней/новой записью. При перезапуске до запуска очереди готовая проверенная копия принимается, незавершённая pending-копия убирается. Уже удалённая/заменённая запись не восстанавливается поздним результатом. Подтверждение повторно проверяет текущую запись и приватную копию. Одновременное изменение учёта приложением исключается NativeMusicGate и AudioExportRuntime.editSaved; активную/поставленную UIDT-очередь сначала нужно приостановить.

## Удаление устаревшего учёта

«Убрать запись» открывает отдельное подтверждение с красной рамкой кнопки. Удаляются только запись files и её ссылки в истории/контрольной точке. Локальные файлы, ВК и состояния задач остаются. Приложение перестаёт считать эту копию скачанной; следующая загрузка может создать новую. Очищенная ранее история при восстановлении не появляется заново.

## Диагностика и проверка

В audio_artwork_item добавлен фиксированный file_reason. audio_file_check сохраняет порядковый номер, фиксированную причину и признак режима поиска; audio_file_recovery — фиксированный результат/код и факт точного совпадения. Ни URI, ни имена, ни пути, ни хеши, ни содержимое документов/ответов ВК не попадают в новые события. Проблемы/предпросмотр панели живут в ViewModel, а постоянный источник списка — SQLite; после перезапуска нужна новая проверка.

Инструментальные сценарии проверяют реальные MediaStore-перенос/переименование, отсутствие/изменение размера/хеша, неоднозначность, сохранение очищенной истории и задач, явный импорт без изменения исходника, изменённые теги, отказ для неаудиофайла, восстановление опубликованной копии после имитации смерти процесса и UI-подтверждение. Используются тестовые аудиофайлы, не аккаунт владельца. Конкретное поведение стороннего файлового менеджера владельца и его перемещённые файлы ещё не проверены.

Ошибка доступа при скачивании и две ошибки получения картинок из предыдущего журнала — отдельные случаи. Эта работа не объявляет их исправленными без журнала соответствующей попытки и проверки.

Документация Android: [собственные медиафайлы](https://developer.android.com/training/data-storage/shared/media), [системный выбор документов](https://developer.android.com/training/data-storage/shared/documents-files).

# Доступность треков и работа вне России/Беларуси — 0.9.18

В «Моей музыке» есть «Проверить недоступные треки». Нижняя панель проверяет точные ID записей с restricted/нулевой длительностью из полностью прочитанной библиотеки, а также FAILED/UNAVAILABLE или DENIED из очереди и соответствующие проблемы поиска дубликатов. Список содержит название, исполнителя и причину. Совпадения по одному имени не подставляются. Аудио эта проверка не скачивает; её нужно дождаться на экране. Остановка сохраняет уже показанные результаты в текущем ViewModel.

По каждому ID вызывается прежний фиксированный audio.getById с текущим музыкальным доступом. Ответы различаются:

- Пустой список: ВК не вернул запись для этого доступа. Это не доказывает удаление или региональную блокировку.
- Свежий is_restricted: сервер ограничил запись. Причина/страна не установлены, даже если в объекте есть URL.
- Нет длительности или ссылки: поток сейчас не подтверждён; причины не угадываются.
- Валидный HTTPS URL разрешённого CDN и доступная запись: ВК вернул ссылку. Это не проверка CDN, полного файла или воспроизведения.
- Отказ метода, неизвестный ответ или недопустимый URL показываются отдельной фиксированной причиной. Ошибка токена, сеть, лимит, капча и подтверждение останавливают проверку, а не помечают весь остаток «заблокированным по региону».

## Загрузка при изменении условий доступа

Раньше очередь и проверка дубликатов прекращали обработку по старому restricted/нулевой длительности до повторного запроса. Теперь прежний ID заново разрешается через текущий аккаунт и соединение. При новом ответе без ограничения используется свежая длительность для Media3. Положительная прежняя длительность по-прежнему должна совпасть; другой ID/некорректная структура не принимаются. Имя, папка, ключ очереди и ID не подменяются. При restricted в свежем ответе загрузка не начинается. Прежние HTTPS/CDN/redirect/размер/время/формат и проверки подписи приложения сохранены.

Использование иностранного аккаунта/соединения не запрещается локальной проверкой страны. В приложении нет списка «иноагентов», проверки SIM/GPS/страны профиля или ограничения RU/BY. Страна регистрации аккаунта неизвестна приложению. Поле country профиля не является доказательством страны регистрации или музыкальных прав; оно не запрашивается для принятия такого решения. Публичная [схема объекта audio от VKCOM](https://github.com/VKCOM/vk-api-schema/blob/master/audio/objects.json) не описывает достоверную причину регионального запрета; внутренний протокол остаётся экспериментальным.

Пользователь самостоятельно выбирает аккаунт и системное соединение, включая свой VPN. Приложение не меняет страну аккаунта, не создаёт прокси, не подделывает IP/заголовки, не извлекает браузерные cookies и не пытается получить поток вопреки свежему запрету сервера. Изменение VPN само по себе не гарантирует других музыкальных прав. После смены аккаунта/сети повтори проверку, затем существующей кнопкой «Повторить пропущенные треки» повтори загрузку очереди. Адрес каждый раз запрашивается заново; старые подписанные URL не сохраняются. Уже успешные задачи не скачиваются повторно.

Если точный ID не возвращается, ручной поиск источника обложки остаётся отдельной функцией и не подменяет аудиозапись. Сохранённая локальная музыка не удаляется.

## Проверки и пределы доказательств

JVM: свежий доступ после старого ограничения, новый restricted даже с URL, пустой ответ/нет URL/неверный ID/опасный домен, фиксированный запрос без поддельных региональных параметров, выбор только проблемных записей, остановка при code 5.

Android: настоящие Media3/MediaStore и локальный MP3. Синтетический свежий разрешённый ответ даёт сохранённый файл несмотря на старые restricted/нулевую длительность; свежий запрет оставляет пропуск без CDN-загрузки. Это не проверка реальных прав иностранного аккаунта, региональных правил ВК или конкретных исполнителей. Такие результаты ещё должен подтвердить владелец на своём аккаунте.

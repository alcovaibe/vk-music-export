# Скачивание в Music — 0.9.2

Владелец подтвердил скачивание и воспроизведение реального MP3 на предыдущей версии. Это основание перейти от выборки 10 треков к полной очереди; успешная массовая загрузка 4449 треков пока не подтверждена.

## Использование

Главный экран → «Открыть мою музыку» или Настройки → «Прямой доступ ВК · эксперимент» → «Проверить музыку». Сохранённый рабочий доступ используется повторно. Выбрать «Скачать всю мою музыку», «Скачать музыку и все подборки» либо открыть подборку и выбрать «Скачать в Плейлисты/Альбомы». Дождаться подготовки списков на экране. Затем системная user-initiated data transfer job продолжает аудио в фоне. Разрешение уведомлений даёт прогресс и кнопку паузы в шторке.

Результат находится в `Music/VK Music Export/`:

- `Моя музыка/Исполнитель — Название.mp3`
- `Плейлисты/Название/…`
- `Альбомы/Название/…`

Папка создаётся при первом сохранении через MediaStore.Audio. Доступ ко всему накопителю не нужен. Готовые файлы остаются после очистки очереди и удаления приложения. Приложение не удаляет их по возрасту, числу или общему объёму. Последние пять на экране — только история отображения. Старый внутренний архив 0.8.x удалён в 0.9.1 отдельной точечной очисткой; новые публичные файлы она не затрагивает. [Границы очистки](CLEANUP-0.9.1.md).

Трек в разных папках занимает место несколько раз. Проверенный локальный файл используется для копии без нового CDN-запроса. Служебные номера и ID больше не добавляются к видимым именам. Позиции и ID остаются во внутренней задаче, включая прежний ключ для совместимости очереди и файлов. Разные подборки с одинаковым очищенным названием получают устойчивые папки `(2)`, `(3)` через приватную SQLite-таблицу. Для повторяющихся файлов приложение выбирает свободное имя с коротким суффиксом; окончательную уникальность при вставке обеспечивает MediaStore. Каталог/имя очищаются от управляющих символов и разделителей, ограничиваются по UTF-8. Реальные цифры/скобки в названии не удаляются. Уже сохранённые файлы не переименовываются; при повторной очереди они проверяются и используются по прежнему ключу. [Подробности 0.9.2](NAMES-0.9.2.md).

Из метаданных трека `album` формируются папки альбомов только с сохранёнными в «Моей музыке» композициями. Это не обещание полного альбома. Явный строковый тип `album`/`playlist` или `album_type` учитывается; неподтверждённые числовые типы не угадываются. Без подтверждённого типа подборка остаётся в «Тип не определён» и требует ручной классификации перед скачиванием (с 0.9.9).

## Полнота и ограничения

API читает до 100 элементов за запрос с явным offset. Общий лимит 10 снят. Смещение увеличивается на число возвращённых позиций, повторяющиеся треки не удаляются. Изменение общего счётчика, пустая преждевременная страница или повтор всей страницы дают явный отказ. Это контроль счётчиков и прогресса, а не атомарный снимок ВК: перестановку при неизменном количестве сервер не позволяет надёжно обнаружить.

Каталог может вернуть меньше подборок, чем объявленный счётчик. Недостающие источники и не прочитанные подборки учитываются в итоге, результат не объявляется полной выгрузкой. Метаданные всего источника готовятся перед созданием очереди; прерванную подготовку нужно повторить. Доступные источники и файлы не считаются доказательством доступа ко всем альбомам аккаунта.

Показ списка остаётся постраничным: тысячи Compose-карточек одновременно не создаются. Локальная коллекция страниц удалена в 0.9.5. Скачивание использует данные музыкального API и постоянную очередь, без промежуточного сохранения страницы.

Один трек обрабатывается за раз. При NETWORK/RATE_LIMIT/HTTP — до трёх попыток с задержкой и новым разрешением URL. Устойчивый сбой сети/доступа/накопителя приостанавливает очередь; постоянная ошибка трека помечает пропуск и позволяет следующему продолжить. Пропуски можно повторить. При отказе доступа выполняется автоматическая попытка повторного выпуска токена; при отказе ВК требуется новый вход. Реальный повторный выпуск владельцем ещё не подтверждён. См. [срок доступа](TOKEN-LIFETIME.md).

Существующий AudioTransfer/Media3 путь сохранён: прямой поток или поддерживаемый HLS VOD, проверка кодека/длительности, SHA-256. MP3 остаётся MP3, AAC сохраняется M4A без перекодирования. Ограничения 100 МиБ и 10 минут на трек, 2000 сегментов и поддерживаемые варианты HLS прежние. Удалённые/недоступные треки не скачиваются.

## Восстановление

SQLite в noBackupFilesDir хранит задачи, состояния и локальные URI. Контрольные точки записываются транзакциями на IO, WAL/synchronous FULL. Токены, access_key и подписанные медиассылки в задачах отсутствуют. Каждая ссылка разрешается в памяти перед текущим треком; доступ читается из прежнего зашифрованного хранилища.

MediaStore-запись создаётся с IS_PENDING=1. После записи, fsync и хэша в SQLite сохраняется подготовленная запись; только затем IS_PENDING=0 и состояние DONE. Если процесс оборвался между публикацией и DONE, файл сверяется по SHA-256 и принимается при восстановлении. Незавершённые скрытые записи и временные файлы удаляются. Уже опубликованные пользовательские файлы не удаляются. Перед повторной задачей готовый файл сверяется по размеру/хэшу.

После системной остановки, убийства процесса или перезапуска нажать «Продолжить скачивание». Позиция очереди сохранена; текущий незавершённый трек начинается заново, сегментного resume нет. Автозапуска после загрузки телефона нет. Android может остановить задачу из-за условий/ресурсов; отсутствие onStopJob при принудительном завершении учтено контрольными точками. Абсолютная сохранность при отказе накопителя/сбросе данных платформой не гарантируется.

## Проверки

JVM: 4449 позиций, короткие страницы и повторы, меняющиеся счётчики, преждевременный конец, повтор ответа, отмена, каталог с недостающими источниками, реальные параметры HTTP count/offset, отсутствие секретов в событиях/задачах, безопасные Unicode-пути.

Android: настоящие MediaStore/SQLite, 12 файлов без ротации, контрольная точка после публикации, отмена перед публикацией, восстановление после повторного открытия БД, готовый файл без повторной сети, реальный Media3 на синтетическом MP3 и копия в альбом, запуск UIDT JobService из видимой Activity. Реальные музыка и токен владельца не передаются в CI. Релизный пайплайн проверяет прежний сертификат и установку поверх опубликованной 0.9.4 (1085), новый главный экран, сохранение старого файла коллекции, публичной музыки, очереди и журналов.

Официальные основания: [shared media и RELATIVE_PATH/IS_PENDING](https://developer.android.com/training/data-storage/shared/media), [user-initiated data transfer jobs](https://developer.android.com/develop/background-work/background-tasks/uidt), [JobService](https://developer.android.com/reference/android/app/job/JobService).

## Очистка последних файлов (0.9.7)

Корзина рядом с «Последние сохранённые файлы» открывает нижнюю панель с подтверждением. «Отмена» оставляет список; «Удалить» в красной рамке очищает только отображаемую историю. Музыка в MediaStore, таблица files для повторного использования, очередь, подготовленные файлы и папки не удаляются.

История хранится отдельно в meta той же SQLite-базы (до пяти записей); прежние установки читают существующие последние файлы до первого изменения истории. Очистка переживает перезапуск. Повторное использование уже готового файла не возвращает его в список; новое сохранение или новая копия появляются. Очистка доступна и при работающем скачивании и не останавливает очередь. Файл, завершившийся после очистки, считается новым сохранением.

## Нижняя панель скачивания (0.9.8)

После создания очереди или нажатия продолжения/повтора приложение открывает общую нижнюю панель. Она доступна через кнопку «Скачивания» на главном экране и закреплённую кнопку со стрелкой загрузки в верхней панели музыкального раздела. Старый блок прогресса внутри длинного экрана удалён.

Панель показывает статус, количество сохранённых файлов из общего числа, процент обработанных позиций (включая пропуски), оставшиеся позиции, текущий трек и полученные килобайты. Для HLS показываются известные номера сегментов; для прямого потока неизвестный полный размер не выдумывается. При завершении доступны итог и пропуски; при паузе — продолжение, повтор пропусков и прежняя очистка очереди с сохранением файлов.

«Свернуть», жест закрытия и системная кнопка «Назад» закрывают только панель. UIDT, уведомление и постоянная SQLite-очередь продолжают работать по прежним правилам. Видимость панели переживает пересоздание Activity в текущем процессе. После перезапуска процесса очередь восстанавливается; открыть панель и продолжить можно вручную. Текущий трек читается из RUNNING-задачи той же базы, без новой схемы. При смене задачи или паузе старый байтовый прогресс очищается.

Пока панель скачивания открыта, метаданные обновлений приложения не проверяются и вторая нижняя панель не накладывается поверх неё. Уже начатое скачивание APK этим не отменяется. Проверки используют синтетические треки и настоящие Compose/SQLite/UIDT на эмуляторе, без реального аккаунта ВК.

## Разделение каталога (0.9.9)

Каталог показан вкладками «Моя музыка», «Плейлисты», «Альбомы». Если ВК не сообщил подтверждённый тип, подборка показана в «Тип не определён»: её можно открыть и выбрать «Это плейлист»/«Это альбом», либо сбросить предыдущий выбор. Решение хранится без токенов и access_key в meta существующей SQLite-базы для пары аккаунт + owner/id подборки. Очередь и файлы не меняются; схема базы остаётся v2. Явный тип ВК имеет приоритет над старым ручным выбором.

Обрабатываются явные строковые type=album/playlist и album_type=album/single/ep. Числовой type не угадывается. Метаданные всех страниц по 100 читаются до разделения; внутри вкладки показаны до 100 объектов с локальной пагинацией. Если каталог неполный, UI сообщает число реально загруженных объектов и не объявляет отсутствующие среди них альбомы/плейлисты отсутствующими в ВК.

Для каждого типа есть отдельное скачивание всех его подборок и выбранной подборки. Неизвестный тип блокирует скачивание отдельной подборки/её трека до классификации. При массовой подготовке неизвестные подборки не направляются в «Плейлисты» и учитываются как не включённые источники: полнота категории не обещается. Существующие файлы и очередь не перемещаются.

Обычное «Скачать всю мою музыку» сохраняет треки в «Моя музыка». Отдельная кнопка «Скачать мою музыку и группы по альбомам» дополнительно создаёт прежние группы в «Альбомы» только из сохранённых песен; интерфейс прямо сообщает, что это не полные альбомы каталога.

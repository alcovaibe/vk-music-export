# Скачивание и очередь — 0.10.0

Откройте **VK Music**, подключите аккаунт и выберите библиотеку, трек или подборку. Дождитесь подготовки списков на экране; затем аудио скачивает системная UIDT-задача. Уведомление и нижняя панель показывают прогресс и позволяют поставить задачу на паузу. «Свернуть» закрывает панель, продолжение после остановки запускается пользователем.

## Файлы и порядок

MP3 и AAC→M4A сохраняются без перекодирования в `Music/VK Music Export`: «Моя музыка», «Плейлисты/Название», «Альбомы/Название». Разные источники с одинаковым названием получают разные устойчивые каталоги. Имя файла — исполнитель и название; коллизии имеют суффикс. Файлы остаются при очистке очереди, истории и удалении приложения.

Новый ключ зависит от account ID, типа/ID источника, ID трека и номера его вхождения. Позиция и название не входят в идентичность: перенос в начало и переименование не создают вторую копию. Старые записи принимаются только по известной связи источника/каталога и проверенному аудио, без поиска по случайному имени. Уже сохранённые файлы не переименовываются.

Каждый источник получает `_Порядок.m3u8`: UTF-8, относительные пути, длительность, порядок и повторные позиции. Неполный экспорт явно помечен INCOMPLETE и количеством выбранных/сохранённых треков. M3U8 обновляется при повторе; изменённый пользователем файл не удаляется. Поддержка M3U8 зависит от внешнего проигрывателя. M4A содержит переносимые title/artist/album; обложки добавляются при доступности.

## Полнота и ошибки

Страницы читаются по 100 с контролем счётчиков, повторных страниц и преждевременного конца. Каталог не является атомарным снимком ВК. Неизвестный тип подборки требует ручной классификации. Группы альбомов из библиотеки содержат только сохранённые композиции.

Полнота аудио сверяется с длительностью каталога, для HLS также с manifest; короткий preview не считается целой песней. Лимиты: 100 МиБ, 10 минут, 2000 сегментов, поддерживаемый VOD MP3/AAC. Для сетевых временных ошибок есть ограниченные повторы со свежим URL; постоянные ошибки трека отмечаются как пропуски. Ошибка доступа/аккаунта/накопителя приостанавливает очередь.

Панель показывает все ошибки постранично по 50. Ошибки чтения источников сохраняются отдельно; «Повторить источник» перечитывает его без сброса DONE других источников. Общий повтор возвращает неудачные задачи в PENDING. Отдельный JSON-отчёт результата содержит все позиции, статусы, ошибки источников, account ID и относительные пути, без токенов/подписанных URL. В отличие от обезличенной диагностики он содержит названия песен; перед отправкой просмотрите файл.

## Аккаунт и восстановление

Новая очередь привязана к проверенному аккаунту. Перед работой проверяется текущий доступ; очередь A не продолжает работу с B. Для старой очереди без владельца показана явная привязка к проверенному account ID. Смена/удаление доступа не удаляет музыку.

SQLite v3 в noBackupFilesDir хранит задачи, состояния, источники и URI, использует транзакции/WAL/synchronous FULL. При миграции v1/v2 сохраняются очередь и учёт файлов. Инициализация повторяется после временной ошибки, ошибка Deferred не отравляет процесс до перезапуска.

Сначала MediaStore-запись скрыта через IS_PENDING, затем fsync/SHA-256, контрольная точка и публикация. После прерывания опубликованная копия принимается по проверке; незавершённая запись очищается. Промежуток между записью QUEUED и JobScheduler защищён от отмены: результат постановки всегда сохраняется. Текущий незавершённый трек скачивается заново.

[Старый архив](CLEANUP-0.9.1.md) сохраняется и переносится отдельно. [Очистка последних сохранений](../README.md) меняет только отображаемую историю, до пяти записей; учёт готовых файлов не ограничен этим числом.

Проверки используют реальные MediaStore/SQLite/Media3 и синтетические файлы на API 36/37. Реальный аккаунт и длительный фон проверяются при [приёмке RC](RELEASING.md).

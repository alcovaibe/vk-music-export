# Приватные обновления 0.6.0

Поведение соответствует обновлятору Bluetooth Disable: проверка при возврате в основной интерфейс раз в 24 часа (попытка фиксируется до сети), ручная проверка с паузой 5 секунд, числовой versionCode, отложенная версия, загрузка только по нажатию, прогресс/отмена/повтор, перепроверка APK на каждом нажатии установки. Сеть/скачивание и проверки файлов выполняются вне Main. Metadata-запрос отменяется при уходе с экрана; поколения не дают запоздалому результату открыть диалог. Загрузка/готовый APK остаются в ViewModel при pause/rotation. Завершение процесса требует повторной загрузки; старый cache очищается до доступности контроллера. Нет WorkManager, сервиса, расписания и скрытой установки.

Источник — фиксированный https://api.github.com/repos/alcovaibe/vk-music-export/releases/latest. Repo и APK приватные. Пользователь вводит fine-grained personal access token github_pat_… в защищённом нативном диалоге: владелец alcovaibe, только vk-music-export, Contents: Read-only, выбранный срок действия. Пароль, классический широкий токен и cookies браузера не нужны. Ввод не saveable и очищается при закрытии. API не позволяет проверить выбранные репозитории токена из самого факта доступа; приложение не заявляет проверку его минимальных прав. Истечение/отзыв/недоступный релиз показывают фиксированную ошибку доступа при ручной проверке. Токен можно заменить/удалить в приложении и отозвать в GitHub.

AES/GCM/NoPadding, новый случайный IV, AAD applicationId, отдельный непереносимый ключ AndroidKeyStore. AtomicFile update-access.bin в noBackupFilesDir; backup/transfer отключены. Нет токена в BuildConfig, preferences, исходниках, APK, аналитике и логах. UI/лог не получает текст сетевых ошибок, заголовки, тела ответов и подписанные URL. Диагностика фиксирует только заданные стадии updater.

Cookie-free OkHttp 4.12.0, HTTPS с платформенной проверкой сертификатов/имени, без interceptor-логов. Bearer только для фиксированных releases/latest и releases/assets/<id> данного repo. Загрузка asset поддерживает 200 или максимум пять HTTPS-редиректов на release-assets.githubusercontent.com/objects.githubusercontent.com:443, без userinfo/fragment. На CDN Authorization и GitHub API headers не передаются. URL с подписью не сохраняется на диск. Metadata ограничено 256 КиБ, build-info 16 КиБ, APK 100 МиБ; точные asset size/SHA-256 проверяются. Проверка latest ограничена 30 с, отдельный JSON call 15 с, download call 10 минут, connect 10 с/read 30 с. Частичные файлы удаляются при отмене/ошибке.

Не принимаются draft/prerelease, чужие теги/имена/дубли APK, неuploaded assets и отсутствующий SHA-256. Поля GitHub API допускаются сверх используемых; build-info имеет ограниченный набор полей, совпадающий с существующим издателем (включая необязательный releaseCommit). Build-info связывает applicationId/versionCode/versionName/minSdk/tag/apk и digest с релизом. Понижение наблюдаемого кода в сессии отклоняется. Перед READY и каждым Install PackageManager сверяет package, текущую installed version, minSdk, точные code/name, debuggable и набор текущих сертификатов; file size/SHA-256 также перепроверяются. Смена ключа пока отклоняется. Окончательную криптографическую проверку и установку выполняет Android.

Отдельный non-exported FileProvider открывает только cache/updates, выдаёт временный READ URI. REQUEST_INSTALL_PACKAGES; если разрешение не выдано, открываются настройки этого источника. После возврата нужен повторный Install. Отмена сохраняет APK. Нет установки без подтверждения и разрешений shared storage. Подпись/пакет/collection schema не меняются.

Проверки: JVM fixtures для tags/metadata/digest/SDK/signature identity, реальной цепочки API/CDN через synthetic interceptor с проверкой headers; контроллер interval/cooldown/отложенных/старых/несовместимых версий, отмены/запоздалых результатов, pause/ready/reverify/token removal. Android: настоящий Keystore (шифрование/повторное открытие/порча/удаление), FileProvider scope/read/installer intents и UI неверного токена без записи доступа/коллекции. Release CI проверяет установку поверх настоящей опубликованной 0.5.3 (1047), сохранность коллекции и журналов.

Тестовые ответы и операции не являются реальным входом/скачиванием с токеном владельца. Токен вводится только на телефоне; для реальной проверки нужен следующий опубликованный более новый релиз. Этот выпуск не исправляет E6 — отдельная диагностика VKM Layout остаётся доступной.

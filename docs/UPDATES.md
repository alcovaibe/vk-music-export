# Публичные обновления — 0.9.4

Репозиторий alcovaibe/vk-music-export публичный. Обновлятор больше не требует GitHub PAT и не читает build-info.json из релиза. Схема повторяет поведение Bluetooth Disable: небольшой публичный JSON описывает стабильную версию, APK скачивается с GitHub Releases по действию пользователя, установку подтверждает Android.

## Источник

Фиксированный URL: https://raw.githubusercontent.com/alcovaibe/vk-music-export/main/docs/updates/android.json

Манифест хранится в `docs/updates/android.json`: schemaVersion, platform, channel, applicationId и release. В release находятся versionName, versionCode, minSdk, tag, apk, size и sha256. Произвольные URL из JSON не принимаются: адрес APK строится из проверенных версии и кода для фиксированного репозитория. Начальный манифест описывает фактически опубликованную 0.9.3 (1080).

Клиент принимает только ожидаемую схему, UTF-8 и ответ не больше 16 КиБ, поддерживает ETag/304. Перенаправления манифеста не разрешены; raw.githubusercontent.com может отвечать `text/plain`, поэтому этот тип поддерживается вместе с application/json. Откат ниже уже полученного в текущем экземпляре клиента кода отвергается.

## Поведение

- Автоматическая проверка при возврате в приложение — не чаще раза в сутки. Попытка фиксируется до сети; ручная проверка также обновляет время последней попытки. Есть выключатель автоматических проверок.
- Ручная проверка имеет интервал 5 секунд. Новее считается версия с большим числовым versionCode и совместимым minSdk.
- Автоматические ошибки не открывают окно; при ручной проверке показывается результат. Поздний ответ после ухода с экрана не возвращает отменённое состояние.
- Скачивание начинается по кнопке, поддерживает прогресс и отмену. После смерти процесса незавершённую загрузку нужно начать заново.
- Перед предложением установки и перед каждым нажатием «Установить» проверяются размер, SHA-256, пакет, версия, minSdk, debuggable и совпадение сертификатов с установленным приложением. Окончательную проверку APK выполняет установщик Android.
- Установка требует штатного разрешения установки из этого источника и подтверждения Android. Если открылись настройки разрешения, после возврата нужно повторно нажать «Установить».

API ВК и его секреты не используются обновлятором. HTTP-клиент обновлений не имеет cookies/кэша/автоматических редиректов и не отправляет Authorization. Допустимы до пяти перенаправлений APK только на HTTPS GitHub CDN из фиксированного списка.

## Переход со старого обновлятора

Версию с этим изменением нужно один раз установить вручную поверх прежней, с тем же пакетом и постоянной подписью. Установленные 0.9.3 и старше продолжают использовать старый приватный протокол обновлений; изменение видимости репозитория само по себе не меняет код установленного APK.

При запуске новый клиент удаляет только старый зашифрованный GitHub PAT (`update-access.bin` и его AtomicFile-остатки) и его ключ AndroidKeyStore `vkm-update-access-v1`. Музыкальный доступ ВК, старый файл коллекции и очередь не затрагиваются. Серверный PAT это не отзывает: при необходимости владелец отзывает его в GitHub.

## Выпуск и обновление канала

`tools/build-release.sh` продолжает формировать build-info.json, SHA256SUMS.txt и публичный сертификат. Проверка установки поверх опубликованной 0.9.4 (1085) формирует upgrade-check.txt. Успешная проверка остаётся обязательным условием публикации.

`tools/publish-release.py` прикладывает к новым релизам только APK, SHA256SUMS.txt и release-certificate.pem. build-info.json и upgrade-check.txt доступны в артефактах Actions; старые релизы не редактируются.

После публикации `tools/update_channel.py` сверяет Latest, размер и digest опубликованного APK с проверенным локальным файлом. Только затем он обновляет JSON в main отдельным коммитом с `[skip ci]`, чтобы не запускать рекурсивный выпуск. Запись использует SHA предыдущего файла и не перезаписывает конкурентное изменение. Старый recovery не понижает Latest или версию канала. Повтор для того же versionCode допускает только идентичные метаданные.

Публикация APK и обновление канала — два шага: если второй отказал, APK уже доступен в Releases, а приложение пока видит прежний канал. Нужно устранить причину и повторить публикационный шаг; ошибка не скрывается и существующий APK не заменяется.

## Проверки и пределы подтверждения

JVM-тесты охватывают схему, идентичность APK, ETag, отсутствие авторизации, ограничение редиректов, неполный HTTP-ответ, интервалы, отмену и повторную проверку перед установкой. Android-тесты проверяют публичный экран без ввода PAT, очистку старого файла и FileProvider. Python-тесты проверяют публикацию канала, digest, запрет отката, конкурентную запись и отсутствие служебных файлов среди вложений релиза.

Эти проверки не подтверждают успешное обновление на физическом телефоне владельца. После ручной установки нового APK это проверяется отдельной реальной попыткой обновления.

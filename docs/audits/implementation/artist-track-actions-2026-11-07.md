# Проверка 336add9 и продолжение F16

Ветка: `fix/audit-stage0-release-delivery-20261104`. Исходный аудит и его критерии не изменяются.

## Что фактически сделал 336add9

- Добавил `MusicCatalogController`, но ViewModel продолжает выполнять `section`, `select`, refresh и pagination самостоятельно. У нового контроллера нет подключения и пути заполнения `state.catalog`; ненулевой `selectPlaylist` всегда прекращается на проверке каталога. Два теста проверяют только смену раздела и возврат в библиотеку. F26 остаётся частичным.
- Добавил `playArtistTrack` и `downloadArtistTrack`, но строки исполнителя не передавали ни один callback. `downloadArtistTrack(track)` вызывал `download(track, 0)`, хотя `ExportLayout.single` требует позицию от 1 и принадлежность текущей странице библиотеки. `PlaybackLists.artist` не предоставлял `PlaybackExport`, поэтому скачивание из плеера также отсутствовало.
- Добавил декларацию capabilities. Она не используется для admission/UI, и значения по умолчанию объявляют supported даже методы с default METHOD. Это ещё не проверенная provider capability matrix: F04 остаётся частичным.
- Передал dispatcher в availability-тесты, добавил R8/Guava изменения и сводную матрицу. Эти изменения сами по себе не подтверждают успешный CI или ручную приёмку всех F01–F30.

## Продолжение F16

Строки треков исполнителя/альбома теперь имеют Play, Download и доступ к имеющейся локальной копии. Используется общий маршрут `PlaybackEntry` → `PlaybackExport` → `downloadPlayback`; отдельный механизм записи файлов не создаётся. Полная видимая очередь передаётся существующему плееру, который сохраняет порядок и фильтрует недоступные записи.

Топ-треки исполнителя используют источник `artist` с ID исполнителя и аккаунтом слушателя, папку «Исполнители/<имя>» и позиции/occurrence именно показанного снимка. Повтор одного ID получает отдельный task key. Альбом сохраняет существующий catalog source/task key, чтобы не создавать другой вариант идентичности для того же альбома. При неизвестном типе альбома доступно воспроизведение, но назначение папки не угадывается.

Состояние исполнителя хранит `readSessionId`, включая частично полученные подписки после timeout. Новая независимая сессия не может открыть старые детали/альбом; подтверждённое продление допускается. Callback передаёт снимок состояния, и ViewModel отвергает его после перехода к другому исполнителю/альбому, смены аккаунта или auth. Перед записью очереди существующий `downloadPlayback` повторно проверяет действующую сессию и владельца.

## Проверки и оставшаяся работа

JVM-проверки покрывают позиции/повторы, отличие от library source, совпадение album task identity, отсутствие аккаунта/сессии, чужие artist details, restricted records, новый вход того же аккаунта и timeout с частичными подписками. Android-контракты добавлены в `SingleTrackDownloadDeviceTest`: конкретная третья запись без перечитывания библиотеки, устаревший callback после Back и новый login до записи очереди.

Локально скомпилированы production Kotlin, JVM-тесты и Android-тесты. Полный запуск JVM-тестов и lint остановлен по просьбе пользователя перед завершением; успешный результат не заявляется. Подключённых Android-устройств не было. F16 не объявляется полностью принятым до Android/реального VK. F26 и F04 этим исправлением не закрываются. Следующий отдельный шаг F26 — закончить Catalog controller с единственным владельцем состояния, session fencing и контрактами независимой отмены; простое подключение текущего пустого `catalog` сломает выбор подборок.

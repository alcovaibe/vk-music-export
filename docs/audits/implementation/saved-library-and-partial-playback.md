# F10, F11, F17: сохранённое и воспроизведение полученной части списка

Рабочая ветка: `fix/audit-stage0-release-delivery-20261104`. Main и релизы не меняются.

## Изменения

- База `audio-export.db`, схема 5. Таблица `files` сохраняет все прежние ключи задач, источники, повторы и JSON. Индекс `file_uris` выбирает только ссылки на нужный физический файл. Обновление тегов/местоположения больше не читает `savedFiles()` и `taskRows()` целиком. Ссылки, подготовленные записи, счётчики, история и журнал M3U обновляются одной транзакцией.
- Отдельный индекс физических файлов `saved_files`: URI, монотонный порядок первой регистрации файла, представитель записи и ревизия. Повторное использование URI, добавление источника, изменение тегов и перемещение сохраняют порядок; удаление последней ссылки оставляет ревизию удаления для наблюдателей.
- Миграции 1–4 не удаляют музыкальные файлы, задачи, источники или контрольные точки. Для старой базы точная история физических скачиваний не сохранялась: начальный порядок восстанавливается по первой сохранившейся записи URI. Это приближение, не выдуманная дата скачивания. Новые файлы получают устойчивый порядок публикации.
- Сохранённые файлы читаются страницами по 100 и показываются до проверки MediaStore. Проверки наличия используют один ограниченный запрос на пакет до 100 URI. UNKNOWN доступен для запуска; отсутствующий/изменённый файл не обозначается готовым. Перед открытием выбранного файла сервис сохраняет проверку владельца, пути, размера и SHA-256.
- Изменения доставляются через уведомление процесса и устойчивый курсор SQLite: пропуск или слияние уведомлений не теряет публикации. Проверка MediaStore работает независимо от чтения новых ревизий. Возврат в приложение обновляет локальные подсказки без отмены выполняющегося прохода.
- Сортировка сохранённого: последняя публикация сверху по умолчанию; альтернативно название (числа, латиница, кириллица), без учёта регистра, с естественным сравнением числовых частей. Выбор сохраняется отдельно от сортировки ВК.
- Собственная музыка и музыка друзей воспроизводимы из уже полученных страниц. Уже загруженные метаданные той же сессии остаются пригодными для запуска и во время ожидания первого ответа обновления; действительный доступ к выбранному ID проверяется при получении URL. Строка запускает выбранную позицию в отображаемом порядке. Поиск друзей сохраняет исходные позиции для скачивания. Повторы не объединяются.
- Очередь содержит задания скачивания и идентификатор сессии чтения; вход заново в тот же аккаунт не разрешает использовать старую очередь для нового подключения. Подгрузка следующих страниц не меняет активную очередь, трек и позицию плеера. Следующая очередь создаётся при явном выборе пользователем.
- Сборка онлайн-очереди и сортировка сохранённого вынесены с главного потока. Ключи заданий скачивания вычисляются лениво, а не для всех 20 000 записей перед началом прослушивания. Поздно завершившаяся подготовка очереди не заменяет более новый выбор пользователя. Показ сохранённого и его обычное воспроизведение не зависят от `busy` проверки ВК или наличия входа.

## Границы

- Действительные операции обслуживания, которые могут переписывать/восстанавливать файлы, сохраняют прежнюю защиту плеера от одновременной записи. Это не проверка библиотеки ВК. Прицельные блокировки отдельных URI вместо общей блокировки обслуживания остаются отдельной задачей.
- Онлайн-воспроизведению всё равно нужны получение действительного URL выбранной записи и буферизация. Доступ ВК, приватность и ограничения API не обходятся.
- F06 (восстановление плеера после гибели процесса), F09 (снимок очереди), F12, F16 и F29 не объявляются закрытыми этим изменением.

## Проверки

Добавлены обязательные Android-сценарии миграций 1–4, отката изменения нескольких ссылок, сохранения порядка при retag/relink, поступления новой публикации во время заблокированной проверки MediaStore, восстановления после пропущенных уведомлений, пакетной проверки MediaStore, индексов и чтения 100/4500/20000 файлов. Два сценария с барьером второй страницы проверяют фактическое состояние ViewModel/контроллера, выбор повторяющегося трека и сохранение происхождения задания. Отдельный сценарий запускает реальный Media3-плеер с третьего непроверенного локального файла без входа ВК и при отключённых действиях скачивания.

JVM-проверки покрывают сортировку, большие числовые части, неизвестную/отсутствующую локальную запись, частичные страницы, сортировку/поиск, повторы, задания скачивания и неизменность выбранной очереди.

Локальный запуск Android-задач 2026-11-05 заблокирован загрузкой Gradle: `Network is unreachable`. Результаты Android и измерения считаются подтверждёнными только после чтения фактических отчётов CI. Производительные измерения пишутся в logcat с тегом `VKSavedBench`; JSON сохраняется и проверяется отдельным CI-шагом для каждого API; абсолютный порог времени не подменяет реальные результаты конкретного эмулятора.

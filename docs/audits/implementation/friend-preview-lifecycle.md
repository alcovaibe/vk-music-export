# F12: жизненный цикл проверок доступности друзей

База: `96ea272e24a9233fde7ddd5621357897146cf17a`, ветка `fix/audit-stage0-release-delivery-20261104`.

## Изменения

Проверки карточек вынесены из FriendMusicController в FriendAvailabilityReader. Он владеет двумя coroutine workers и поколением запросов. Контроллер сохраняет загрузку профилей, страниц, подготовку очереди и публикацию UI; это очередной небольшой шаг F26, а не завершение всего архитектурного разделения.

Предварительные музыкальные запросы выполняются только для видимых карточек корневого экрана друзей, когда Activity возобновлена. Предзагрузка списка друзей не запускает обход всех их музыкальных библиотек. Открытие профиля, уход в другой раздел, полноэкранный плеер, окна доступа/о приложении, ON_PAUSE и pauseRead отменяют workers. Существующий HTTP-транспорт закрывает отменённый OkHttp Call. Смена видимых карточек отменяет прежний проход; ожидающие запросы старого прохода не продолжаются.

При возвращении заново проверяются незавершённые карточки. Подтверждённые результаты той же read session и аккаунта повторно используются с прежним TTL 15 минут; явное обновление сбрасывает кэш статусов. Кэш остаётся в памяти. Ошибки сети и rate limit не кэшируются как запрет доступа. Скрытым и незапрошенным карточкам искусственный отказ не назначается.

Перед запросом, после результата и перед обработкой ошибки повторно проверяются сессия, аккаунт и поколение. Проверенное продление прежней сессии допустимо; logout и независимый вход не принимают старый успех или отказ. Даже некооперативный поздний ответ после отмены не публикуется. Его finally не меняет список попыток нового поколения.

Скачивание, SQLite, форматы файлов, общий pacer ВК и классификация кода 201 не меняются. F21 остаётся отдельным пунктом. Изменений main, Releases и номера версии нет.

## Проверки

- Семь JVM-сценариев: остановка двух workers, отсутствие новых запросов после паузы, границы видимых карточек, TTL, поздние успех/отказ, logout/новый вход, проверенное продление, busy gate, rate limit. Отдельный сценарий использует настоящий VkAudioClient/OkHttp с блокирующим interceptor и требует отмены actual Call.
- Три Android-сценария проверяют настоящий FriendMusicController и зашифрованный MusicAccessStore: пауза/возврат и повторное использование кэша, профиль/скрытый экран/назад, logout и вход другого аккаунта.
- Дополнительный Compose-сценарий FriendsMusicDeviceTest переключает настоящую навигацию «Друзья → Сохранённое → Друзья» и проверяет отмену и возобновление previews.
- Все четыре Android-имени обязательны для verifier на каждом API; отсутствие или skip не заменяются общим числом тестов. Существующие проверки сохранены.

Локальные Python-проверки и diff-check выполняются перед отправкой. Gradle не смог загрузить дистрибутив 9.8.2 (`Network is unreachable`), поэтому успешные JVM/Android/R8/Lint результаты должны подтверждаться GitHub Actions конкретного нового SHA. Реальный аккаунт ВК, физический телефон, TalkBack и длительная OEM-приёмка здесь не заявляются.

## STOP после восстановления плеера

В прогоне `76f2fba` / `42242320926` стек остановки показал настоящий вызов Player.stop через MediaSessionStub, уже после seek/prepare нового трека. Это внешняя команда MediaSession, не доказательство поломки shuffle/decoder. Код Media3 повторно использует default session ID в PendingIntent; fallback сервиса может направить действие старого уведомления текущей сессии.

Сессии получили отдельный ID на время жизни сервиса. Перед Media3 обрабатывается только помеченная команда STOP от закрытия уведомления: при несовпадении адреса с текущей сессией она игнорируется. Аппаратные кнопки, команды виджетов и остановка текущего уведомления проходят обычным путём. Причинность всех прошлых тайм-аутов пока не объявляется установленной; следующий CI проверяет этот вариант исправления.

Новый обязательный Android-сценарий воспроизводит старое закрытие после пересоздания и проверяет, что играющая очередь сохраняется. Затем он требует реального STOP от текущего уведомления, явного возобновления и STOP без notification extras (гарнитура/системная кнопка). Прежний тест всех перестановок сохранён без ослабления. Журнал команд ограничен 32 записями в памяти и не содержит токенов, адресов медиа или названий треков.

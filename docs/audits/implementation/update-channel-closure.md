# Канал обновлений: условия закрытия

Рабочая ветка: `fix/audit-stage0-release-delivery-20261104`. Изменения main и выпуск релиза требуют отдельного разрешения владельца.

## Что проверяется автоматически

1. Точный JSON-контракт Python совпадает с Android: дополнительные поля и неверные типы запрещены.
2. Проверка кандидата получает Latest и анонимно скачивает его публичный APK. Проверяет размер, SHA-256, криптографическую подпись через SDK apksigner, закреплённый сертификат и реальный AndroidManifest (package/version/minSdk/debuggable).
3. Реальная доставка отдельно читает тот же raw URL main, который читает приложение. Подготовленный JSON или открытый PR не считаются доставкой.
4. Публикация указателя восстанавливается после сбоя каждого шага. Закрытый PR, посторонние изменения, изменившийся head, другая подпись или замена байтов той же версии останавливают процесс. Автоматика не пишет в main и не сливает PR.
5. Ручной запуск CI привязан к проверенному полному SHA; перемещение ветки до запуска отклоняется.
6. На одноразовых AVD API 29–37 отдельный тест использует настоящие подписанные публичные APK 1343 → версия кандидата. Проверяет GithubUpdates (включая отказ другому реальному сертификату), FileProvider, системный установщик, сохранность UID и приватного файла.

Транспорт Android в этом тесте детерминированно отдаёт байты, заранее анонимно скачанные и проверенные на CI. Это не проверка сети конкретного телефона/оператора. Права установки выдаются только тестовому host на одноразовом AVD. Подтверждение установки выполняется через настоящий интерфейс Android. Приватный ключ production не нужен и не используется.

## Граница готовности

Нельзя объявлять 100% до выполнения всех условий:

- зелёные проверки текущего SHA, включая весь updater matrix;
- отдельно одобренное слияние указателя в main и успешная проверка публичного raw JSON/APK после слияния;
- включённая защита main (файл ruleset в репозитории сам по себе ничего не включает);
- проверка на физическом устройстве пути разрешения установки/скачивания/установки с сохранением реальной библиотеки;
- долговременное хранение доказательств релиза (F27), а не только ограниченный срок Actions artifacts;
- ручная приёмка реального аккаунта перед следующим stable (F05 остаётся самостоятельным условием).

Старые версии не меняются задним числом. Текущий стабильный APK не содержит новые исправления до отдельно разрешённого выпуска.

# F13: скачивание одного трека без повторного чтения источников

Ветка: `fix/audit-stage0-release-delivery-20261104`.
Основа: `d8c2ef595e08106fae4a7bb82f72002c3ac1bdef`.
Main и Releases этим изменением не обновляются.

## Причина задержки

`NativeMusicViewModel.download(track, position)` заново проходил все страницы
библиотеки/подборки, а для подборки сначала перечитывал каталог. Затем строил
весь список `AudioExportTask`, чтобы оставить одну позицию. Поэтому даже после
анализа нажатие «Скачать этот трек» снова запускало большой проход.

## Поведение после изменения

`ExportLayout.single()` создаёт ровно одну задачу из уже показанного снимка.
Проверяется точное совпадение записи с указанной позицией; номер повторного
вхождения считается по загруженному префиксу в памяти. Сортировка интерфейса
не меняет исходную позицию. Ключ, папка, источник и occurrence совпадают с
прежней массовой подготовкой того же снимка. Полная очередь и тысячи её ключей
ради одной песни больше не создаются.

Это **скачивание точного ID из показанного снимка**, а не подтверждение текущего
состава удалённой библиотеки/плейлиста. Если запись переместилась или убрана
из подборки, не подставляется другая песня с её новой позиции. Контекст и порядок
относятся к показанному снимку; актуальная доступность самого ID проверяется
существующим `resolve()` в движке перед сетевым скачиванием. Неизменность
состава источника не предполагается и не доказывается отсутствием запроса.

Подготовка использует проверку владельца аккаунта (`accountOwner`; в production
это существующий `users.get`), но не вызывает libraryPage, playlistPage,
currentCatalog или downloadedCatalog. При действующей сессии без повторов это
одна проверка аккаунта, независимо от количества страниц библиотеки.
Протоколы авторизации/разрешения аудио и список методов VK не расширяются.

Снимок теперь связан с readSessionId. Новый вход, даже того же аккаунта,
не может использовать снимок предыдущего входа. Допускается существующее
проверенное продление той же read session. После асинхронной проверки аккаунта
сессия проверяется ещё раз. Отмена, чужой аккаунт, выход во время запроса или
незавершённая очередь останавливают подготовку до замены очереди.

## Повторное использование аудио

`SavedAudioReuse` и проверки SHA-256/владения файлами не ослаблены. Для одного
VK ID библиотека, альбом, разные плейлисты и друзья могут ссылаться на один
физический URI. Расширенный тест движка использует шесть таких источников и
проверяет один запрос медиа, одно разрешение URL, один URI и шесть отдельных
ссылок источников. Объединение разных VK ID по имени этим не добавляется.

Существующие файлы, БД, migrations, настройки папок и правила M3U8 не меняются.
Правила формирования M3U8 для очереди остаются прежними: очередь из одного
выбранного трека не считается полным экспортом текущей подборки.

## Проверки и границы

- Пять новых JVM-тестов: 100/4500/20000 позиций, совпадение идентичности с
  массовой подготовкой, дубликат в префиксе, альбом/плейлист, неверная позиция,
  изменённые метаданные, неполный снимок и недоступная запись.
- Семь новых instrumentation-тестов реальной ViewModel и SQLite: запрет
  повторного чтения списков после анализа, изменённый удалённый список,
  чужой аккаунт, новый вход того же владельца, logout во время проверки,
  cancellation и сохранность незавершённой очереди. Только запуск фонового
  задания подменён; настоящий transfer/reuse проверяется отдельным тестом движка.
- Существующий UI-тест сортировки сохраняет проверку исходной позиции.
- Локально: 126 Python-тестов прошли, 3.220 секунды; `git diff --check` прошёл.
- Локальный запуск JVM-теста остановился до компиляции: wrapper не смог скачать
  Gradle 9.8.2 (`Network is unreachable`). Kotlin/Android-проверки должны быть
  подтверждены Actions на точном SHA. Эта ошибка не объявляется успехом.

Закрывается только ветвь F13 для одиночного скачивания из своей библиотеки
и открытой подборки. Повторное чтение при открытии подборок, подготовке массового
экспорта и в контроллере друзей остаётся отдельной работой. Реальный VK-аккаунт,
пропускная способность сети и физическое устройство здесь не проверены.

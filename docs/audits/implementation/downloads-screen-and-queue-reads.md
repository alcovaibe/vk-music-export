# F09 и F18: чтение очереди и самостоятельный экран загрузок

Ветка: `fix/audit-stage0-release-delivery-20261104`. Main и релизы не изменяются.

## F09

Схема `audio-export.db` 6 сохраняет задачи, музыкальные файлы, источники, ошибки, историю и контрольные точки схем 1–5. Новый `queue_counts` содержит счётчики состояний; триггеры обновляют их и ревизию очереди в той же транзакции, что и изменение задания. Счётчик ошибок источников также транзакционный. Замена/очистка очереди меняет её идентификатор. Изменение связанного файла обновляет ревизию страницы готовых заданий.

`snapshot()` читает только сводные значения, не более пяти недавних файлов и одно текущее задание. Ошибки и источники больше не входят в частые снимки прогресса. После записи отдельной истории это три SELECT; старый резервный путь истории добавляет один ограниченный запрос LIMIT 5. Счётчики не требуют полного обхода tasks при каждом обновлении.

Отдельное чтение страницы возвращает до 50 записей для очереди, ошибок или завершённых заданий. Подробности ошибок выбираются JOIN по ключу meta; источники и треки делят один лимит страницы. Для ожидающих заданий добавлен частичный индекс порядка. Список не перечитывается при изменении только полученных байтов. Закрытый экран и Activity в фоне прекращают чтение; устаревшая страница другой очереди не публикуется. Повтор источника проверяет идентификатор очереди перед применением результата.

Полный JSON-отчёт использует отдельные соединённые курсоры и пишет записи последовательно. Он содержит все задания и подробности ошибок, а не только текущую страницу. Согласованность сохраняется существующей SQLite-транзакцией; во время явного экспорта она может кратковременно задержать запись очереди. Каждый экспорт получает отдельный файл; незавершённый файл удаляется при ошибке. Музыкальные файлы не удаляются.

## F18

Верхняя кнопка, автоматическое открытие после запуска и нажатие уведомления ведут на самостоятельную страницу «Загрузки». Нижняя панель сохраняет три раздела. Система Back возвращает к разделу, откуда открыли загрузки; маршрут, вкладка и страница используют rememberSaveable. Повторное создание Activity сохраняет экран. Тёплое уведомление обрабатывается как одноразовое событие без замены исходного Intent запуска; тест отправляет настоящий PendingIntent, проверяет сохранение экземпляра Activity и затем её пересоздаёт. Ранее обработанное уведомление обслуживания не перехватывает восстановленный маршрут.

Оформление следует согласованному концепту: тёплая светлая палитра, округлая карточка общего прогресса, вкладки «Очередь / Ошибки / Готово», карточка текущей загрузки, постраничный список и существующий мини-плеер. При fontScale ≥ 1.3 вкладки занимают отдельные строки на всю ширину, сохраняя целые слова; выбранная вкладка отмечена в семантике TalkBack. Вкладка ошибок сохраняет повтор источника, повтор неудачных треков и полный отчёт. Очистка очереди явно сохраняет файлы. Готовый файл можно открыть с прежней проверкой владельца и SHA-256.

Размер всего файла и скорость не выдумываются. Текущий контракт AudioProgress предоставляет полученные байты и, для HLS, число сегментов: определённый процент показывается при известном количестве сегментов; для остальных стадий используется неопределённый индикатор с фактическим количеством данных.

## Проверки и ограничения

Обязательные сценарии CI: миграция v5→v6 плюс прежние миграции v1–v4; транзакционные счётчики и откат; повреждённая запись вне читаемой страницы; все ошибки/источники в полном экспорте; 100/4500/20000 ошибок с числом SQL-запросов; отсутствие повторных чтений на байтовом прогрессе; отмена устаревшей страницы; переходы из сохранённого/друзей и уведомления; пересоздание Activity; крупный текст; очистка без удаления файлов; реальное офлайн-воспроизведение через переходы.

Замеры пишутся в `VKQueueBench` и проверяются `tools/extract-queue-benchmarks.py`. Для каждого API обязателен JSON с тремя размерами. Измеряется чтение SQLite, включая подготовку снимка/страницы и полный курсор отчёта; это не Macrobenchmark холодного запуска и не время получения музыки из ВК.

Локально Android-задачи не запустились: загрузка Gradle завершилась `Network is unreachable`. Результаты Android, R8 и Lint подтверждаются только фактическим CI. Реальный VK-аккаунт и аппаратное убийство процесса здесь не объявляются проверенными. F06 (устойчивое восстановление плеера) остаётся отдельной задачей.

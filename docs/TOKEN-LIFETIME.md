# Срок доступа ВК и повторный выпуск токена

При получении токена сохраняются присланные ВК expires_in (секунды) или expires (секунды/Unix-время). Ноль и отсутствие поля означают неизвестный срок, а не бессрочную гарантию. Срок одноразовой заявки pairing не используется как срок музыкального токена. В музыкальном разделе отображается известная дата либо отсутствие данных, возможность автоматического обмена и необходимость нового входа.

В текущем протоколе Chrome подтверждает pairing; нативный connect_code_auth выдаёт промежуточный auth_token, а фиксированный login.vk.com/?act=web_token выпускает музыкальный токен для прежнего app_id 6287487. После нового успешного входа сохраняются промежуточный токен и ограниченный набор cookies только нативного обмена, вместе с ID аккаунта. Они зашифрованы AES-GCM тем же AndroidKeyStore-конвертом в noBackupFilesDir; профиль Chrome не читается. При удалении доступа удаляются и эти данные. Cookies не передаются музыкальному API, CDN или обновлятору. Диагностика содержит только фиксированный этап, без токенов/cookies/ответов сервера.

За пять минут до известного истечения, а также при ACCESS/code 5 во время музыкального запроса выполняется попытка повторного web_token-обмена. Проверка на активном приложении идёт раз в минуту; перед API-запросами, включая UIDT-очередь, срок проверяется отдельно. Новых workers, alarms и постоянного фонового таймера нет. При неизвестном сроке нет выдуманного обратного отсчёта; попытка возможна при отказе API.

Новый результат проходит users.get/audio.get и проверку того же аккаунта, затем атомарно заменяет прежний доступ. Mutex объединяет одновременные попытки UI/очереди; один API-запрос повторяется не более одного раза. Ошибки сети сохраняют ещё действующий токен и дают паузу 5 минут. Отказ обмена/музыкальных прав блокирует новые автоматические попытки до повторного входа. Выход или другой вход во время обмена не может быть отменён поздним результатом: сохранение сравнивает ID прежнего конверта.

Старые конверты с token/agent продолжают читаться без искусственного срока. Для появления материала продления потребуется новый вход через Chrome. Ручной токен не даёт автоматически права на продление. VK ID OAuth refresh_token из другого протокола не подставляется в этот обмен.

Повторный выпуск использует тот же фиксированный запрос, что уже применяется для первичного музыкального доступа; CI проверяет его на синтетических ответах. Принятие сохранённого промежуточного доступа сервером ВК при повторном выпуске на реальном аккаунте пока не подтверждено. ВК может отозвать оба токена или потребовать новый вход в любой момент; гарантии непрерывного продления нет. Ни токены, ни аккаунт владельца в CI не используются.

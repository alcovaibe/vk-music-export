# Совместимость Android 10–17 (API 29–37)

Этот документ описывает **исходный код**, а не уже опубликованные APK. Исторические релизы и `docs/updates/android.json` сохраняют исходные данные и сертификаты. Поддержка новой минимальной версии считается подтверждённой только после зелёного CI и ручной приёмки.

## Системный транспорт

| SDK | Выполнение скачивания и сканирования дубликатов |
| --- | --- |
| 29–33 | Приватный Foreground Service с типом `dataSync` и постоянным системным уведомлением |
| 34–37 | User-Initiated Data Transfer Job (`setUserInitiated`, `JobService.setNotification`) |

`BackgroundTransport` выбирает механизм без переноса основной логики из `AudioExportEngine` и `DuplicateCheckTask`. Существующие проверки аккаунта, SQLite-транзакции, контрольные точки и контроль файлов остаются основными источниками истины. Запуск FGS выполняется по действию пользователя; отказ Android фиксируется и должен переводить очередь в приостановленное состояние. Нет автоматического перезапуска вопреки системным ограничениям.

`POST_NOTIFICATIONS` запрашивается только с API 33. Типы FGS и сервисы в AndroidManifest не экспортируются наружу.

## MediaStore, API 29

Android 10 использует `MediaStore.setIncludePending(uri)` для чтения `IS_PENDING`. На API 30+ используется `MediaStore.QUERY_ARG_MATCH_PENDING`. Проверки `OWNER_PACKAGE_NAME`, `RELATIVE_PATH`, размера, SHA-256 и операций сохранения/редактирования файлов сохраняются. Приложение не получает `MANAGE_EXTERNAL_STORAGE`.

`InputStream.readNBytes()` на API 29 недоступен: чтение JSON, кеша и аудиосигнатур перенесено на `readAtMost()` с теми же ограничениями максимального размера. Для системных панелей используется совместимый путь установки светлых статусных и навигационных значков.

## Проверки

Команда локальной сборки при установленном SDK 37:

```sh
python3 -m unittest discover -s tools -p 'test_*.py'
./gradlew --dependency-verification strict testDebugUnitTest lintDebug lintRelease assembleDebug assembleRelease assembleDebugAndroidTest
```

GitHub Actions запускает отдельные инструментальные проверки на API 29–37. Каждый API должен иметь собственный отчёт и не может считаться пройденным по чужой сборке. `tools/verify-instrumentation.py` блокирует пропущенные, ошибочные и неполные тестовые наборы. Проверка реальной авторизации ВК требует разрешённого тестового аккаунта; CI использует синтетические запросы.

На API 29–33 проверить жизненный цикл FGS, приостановку из уведомления, запись/восстановление MediaStore и работу без разрешения `POST_NOTIFICATIONS`. На API 34+ проверить неизменность UIDT. Обновления со стабильной версии проверяются только там, где исходный APK допустим по minSdk (отдельный эмулятор API 36 в существующем релизном workflow); старые APK не разрешается считать совместимыми с Android 10 задним числом.

## Ограничения доказательств

Отсутствие ошибок компиляции, Android Lint или одного эмулятора **не подтверждает** все устройства и OEM-прошивки. Устойчивость к принудительной остановке Android не гарантируется: продолжение после явного запуска и сохранение контрольных точек обязательны. Итоги реального CI и приёмки фиксируются в PR.
